**Новая функция**: `generate_training_data_real()`

**Возможности**:
- Загрузка реальных метеоданных из Open-Meteo API
- Запуск гидрологического моделирования на реальных данных
- Присвоение меток на основе исторических событий паводков

- Запасной вариант с пороговым методом (если нет базы данных паводков)

**Использование**:
```python
from src.models.ml_predictor import generate_training_data_real
from src.data.flood_database import load_kyrgyzstan_floods

# Загрузка исторических паводков
floods = load_kyrgyzstan_floods('data/FloodArchive.csv')

# Генерация обучающих данных
training_data = generate_training_data_real(
    region='chui',
    start_date='2018-01-01',
    end_date='2023-12-31',
    flood_events=floods
)
```

### 3. Скрипт обучения (`scripts/train_real_data.py`)

**Статус**: ✅ Полностью реализован и протестирован

**Возможности**:
- Автоматическая загрузка реальных данных
- Обучение ML модели
- Сохранение обученной модели
- Вывод метрик и важности признаков
- Поддержка командной строки

**Использование**:

```bash
# Базовое использование (регион Чуй, 2018-2023)
python scripts/train_real_data.py

# С параметрами
python scripts/train_real_data.py \
  --region osh \
  --start 2015-01-01 \
  --end 2024-12-31 \
  --model ensemble \
  --optimize

# Справка
python scripts/train_real_data.py --help
```

**Доступные параметры**:
- `--region` - регион (chui, issyk_kul, naryn, osh, jalal_abad, talas, batken)
- `--start` - начальная дата (YYYY-MM-DD)
- `--end` - конечная дата (YYYY-MM-DD)
- `--model` - тип модели (rf, xgb, lgb, ensemble)
- `--optimize` - оптимизация гиперпараметров
- `--dfo-path` - путь к базе данных DFO

## 📈 Сравнение: Синтетические vs Реальные данные

### Синтетические данные (текущий подход)

**Преимущества**:
- ✅ Всегда доступны
- ✅ Контролируемые сценарии
- ✅ Быстрая генерация
- ✅ Нет зависимости от внешних API

**Недостатки**:

- ❌ Искусственные паттерны
- ❌ Переоптимизм метрик
- ❌ Не учитывают реальную климатическую вариативность

### Реальные данные (новый подход)

**Преимущества**:
- ✅ Отражают реальную погоду Кыргызстана

- ✅ Честные метрики производительности

- ✅ Учитывают климатическую вариативность

**Недостатки**:
- ❌ Требуется интернет (для первой загрузки)
- ❌ Зависимость от Open-Meteo API

- ❌ Требуется база данных паводков для лучшего качества

**Рекомендация**: Использовать **реальные данные** для финальной модели и дипломной работы, синтетические - для быстрого тестирования.

## 🐛 Известные ограничения

### 1. Доступность базы данных DFO

**Проблема**: Сайт DFO обновлен в январе 2026, прямая загрузка недоступна

**Решение**:
- Запросить данные по email (kettner@colorado.edu)
- Использовать альтернативные источники (EM-DAT, МЧС)
- Временно работать с пороговым методом

### 2. Дисбаланс классов

**Проблема**: Паводки - редкие события (~2-5% данных)

**Решение**:
- Система автоматически использует class_weights
- Можно применить SMOTE oversampling
- Уже реализовано в FloodMLPredictor

### 3. Региональная специфика

**Проблема**: DFO может не иметь детальной информации по регионам Кыргызстана

**Решение**:
- Использовать все события для Кыргызстана
- Получить региональные данные от МЧС
- Использовать buffer_hours для учета неточности
